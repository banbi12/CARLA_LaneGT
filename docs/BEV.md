# BEV 范围配置

默认范围为 `[-15,-30,15,30]`，单位米、顺序 `[xmin,ymin,xmax,ymax]`，x 向右、y 向前。支持对称或非对称矩形，不仅限于 30×60 米。

```bash
python run.py check --limit 1 --topdown-only --bev-range -16 -31 16 31
python run.py extract --limit 1 --topdown-only --centerline generate \
  --bev-range -16 -31 16 31 --output outputs/gt_32x62
python run.py review --source outputs/gt_32x62 --output outputs/review_32x62
```

矩形的四个边界必须有限，最小值小于最大值。采样、渲染、页面编辑、CAD 参考框与回导边界读取 GT 中的 `BEV_range_m`，不得只修改图上的白框。图册采用等比例缩放和留白，不拉伸道路形状。后处理按源 GT 范围执行，无需再次传参。

## 顶视覆盖校验

semantic 提取前将请求矩形在 z=0 地面上的四角通过完整车辆位姿和实测顶视内参投影，必须落在图像四周 48 像素安全边缘以内。使用地面交点而不是假设模型 z=0 等于世界 z=0，保留车辆 z/pitch/roll 的影响。参考审计记录实际角点与投影坐标。

不满足覆盖时会在创建提取输出目录前拒绝。范围扩大仍可能增加实例数、采样表示误差和人工审核量。程序不自动提高相机，也不伪造超出视场的几何。请缩小范围，或调整采集高度/位置后重新采集并复核。已有顶视像素中的遮挡和语义质量仍需审核；覆盖通过不等于所有地面都可见。

## 下游接口

仅在可选 MapTRv2 适配时，实际采样器使用包含 ROI 的对称夹取包络，以兼容 MapTRv2 以零为中心的 clamp 实现；输入几何始终先裁剪到请求 ROI，因此非对称范围也保持原模型坐标，不偷偷平移标注。Dataset 适配器在 aux_seg 关闭时使用相同采样包络，真实 pc_range 仍应对应实际请求范围。非对称范围的辅助分割训练暂不支持。

改变范围不会自动修改外部模型的 pc_range、BEV 网格分辨率、位置编码或训练配置。训练前需同步调整；通用完整几何没有128实例上限；可选 MapTR 容量超过128时报告且不截断。已有逐帧中心线标签可能只覆盖旧区域；自动中心线会按新范围重新裁剪世界几何。

图册和 CAD context 都记录范围。缺少范围的旧文件按原 30×60 米处理；带不同范围或被移动的 CAD 参考框会被拒绝，不能通过修改配套 JSON 绕过源 GT 的边界检查。

目前仅在 CARLA 0.9.16 的 Town10HD/Opt 上完成验证；其他城镇和版本尚未验证。当前默认资源和采集配置对应这一验证环境，接入其他地图须先适配并验证，不能仅改名称或摘要。相机、BEV、提取、分段和导出参数的实际生效位置及修改影响见[参数索引](PARAMETERS.md)。

XODR-only 纯世界/逐帧几何提取不需要图像覆盖；使用相同顶视图册时才检查地面 ROI 在相机中的覆盖。相机分辨率、FOV 的实际控制点见参数索引，不能只改 cases 描述字段。
